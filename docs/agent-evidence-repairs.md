# Agent 证据与上下文修复

基线：`2f1bc9558dc783a9567c307b1f42130006294cb7`。本变更在隔离工作区实施，尚未部署。

## 已实现的边界

- 人物过滤不再零命中后放回全部候选，显式记忆查询不静默移除人物/时间条件。
- 相关性阈值补齐仍可服务内部召回，但与可展示的记忆证据分开；无匹配是正常结果。
- query_memory 保存通过范围/证据门控的完整命中内容，返回有限预览及 `read_tool_result` 句柄；被拒候选仅保留 ID/原因，不让续读将其正文误当证据。
- GPT 搜索插件在自身进程保存完整安全响应，提供 `gpt_read_search_result`；不能把插件进程内存当成主进程 singleton。
- 续读的范围来自宿主真实会话，过期或异群句柄明确失败；原文句柄不会在进程重启后误指新内容。
- 最终请求经过 hook 后统计可见输入与工具定义字符数；服务端实际报告的 prompt_tokens 在 after_response hook 前读取。
- 高水位触发已完成工具轮的整体归档。当前活动轮的用户锚点、原生 reasoning、function call/output、媒体和 replay 保持完整。
- 摘要失败不提交裁切；同批未改变的失败材料不反复请求摘要。
- 原消息锚点、后续到达消息和实际工具回执形成有界内部参考。保留单 Agent 直接填写 reply.text，现有人格不变。
- 可见正文不再被固定“重新思考”文字替换。

## 配置

配置 schema 升为 `8.15.64`，字段由配置模型生成，无新增迁移 Hook。

- `chat.context_visible_char_high_watermark = 120000`
- `chat.context_prompt_token_high_watermark = 48000`

这两个值是整理触发阈值，不是模型硬上下文上限，也不是质量最优值。可见字符不包括图片或 opaque provider payload；不能按密文大小伪造 token 数。活动轮单独超额时保留协议并记录警告，不能为了满足阈值丢掉正在使用的证据。已有实例应只合并必要设置，不覆盖端点、密钥或账号。

## 尚未证明或尚未实现

- 任务参考记录的是宿主观察到的消息/工具回执，不是完整语义任务规划器；不自动把工具成功升级成事实确认。
- 未增加自动识别多话题关系或每次发送前的语义纠正裁决。工具期间新消息会进入下一轮模型上下文，但不能声称已杜绝所有过时发言。
- 重复回执计数仅检测工具名、参数与结果完全相同，不是语义信息增益检测；生成新句柄也会改变指纹。
- 没有换模型/执行器，没有恢复 Planner→Replyer，没有让辅助模型二次改写所有证据。
- 原文存储是内存暂存，重启或淘汰后会明确失效，不提供跨重启持久检索保证。原生存储仍为每会话 20 条，尚无活动句柄固定或全局字节上限；GPT 插件另有每会话 20 条、全局 128 条/400 万字符、单结果 50 万字符上限。
- 这里只做隔离确定性测试；没有真实模型请求、QQ 测试消息或生产升级。自然度、梗理解与搜索质量提升还需固定记忆快照、按消息到达时序回放验证，不能提前引入未来学到的内容。
