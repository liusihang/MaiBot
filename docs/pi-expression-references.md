# Pi 主 Agent 的表达参考

表达库现在直接接入 Pi 的自动参考构建，不恢复 Planner → Replyer，也不调用表达选择子 Agent。

1. 从当前真实聊天流读取表达使用开关与已有共享范围规则；仅学习开关不影响已有表达的使用。
2. 复用表达库的精选限制、内容规范化与示例过滤，并排除已拒绝的审核记录。
3. 最近八条同群真实消息与本批新消息提供最多 2,000 字符查询。工具结果、注入记忆和外群消息不是表达查询材料。
4. 快速模式（`use_vector_expression=false`）本地按场景/说法的文字重合排序，再以频次和稳定 ID 排序；没有文字重合时可给出少量本群惯用表达。它们是供主 Agent 判断适用性的候选，不是语义匹配保证。没有额外模型调用。
5. 向量模式复用已有表达索引与 embedding 查询，只返回当前可用、内容一致的条目，不再由另一个 LLM 精排。一条有效已索引表达也能检索。索引无结果就返回空，不偷偷改成随机选择；检索超时或已知运行错误会记录警告，本轮省略可选表达。
6. 最多两个不同说法作为独立 `expression` 来源参考。内容或来源版本改变才形成新版本，沿用 Pi 增量追加与去重。所有表达与记忆等参考仍共享三条、2,400 字符上限；事实参考优先占用预算。
7. 主 Agent 根据本轮意图、关系与语气决定采用、改写或忽略。表达不能证明个人经历、改变权限或成为系统指令。返回候选不记作已经实际使用。

这使原先只学习、未被 Pi 普通回复消费的表达库有了实际使用入口。并不保证每轮必须说一句已学表达，也不修改已提交的会话历史。

离线验证：`pytest -q pytests/maisaka/test_pi_expression_references.py pytests/maisaka/test_pi_expression_small_index.py pytests/maisaka/test_pi_references.py`。覆盖真实参考构建入口、开关与审核过滤、同群上下文、零结果、稳定版本与更新、共享预算优先级，以及单条索引的真实向量排序。未调用线上模型或修改运行配置。
