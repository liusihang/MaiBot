# Pi 主 Agent 的群表达检索

表达与黑话通过 `query_group_expressions(intent, context?, limit?)` 统一使用。主 Agent 每次发言前先决定自己想表达的意思，再调用查询工具，阅读候选的含义、场景和真实例句，最后自己组织回复。查询是每次发言前的固定步骤，是否借鉴候选由主 Agent 判断；没有合适的、结果为空或查询失败时，按原有想法表达。继续使用 Pi 单 Agent，不增加表达选择或改写 LLM。

- `intent` 为 1–1,000 字符；可选 `context` 最多 2,000 字符，`limit` 为 1–6（默认 6）。真实会话来自宿主 runtime，模型不能指定其他群。共享范围及可用状态在检索层过滤，不允许用外群原始聊天充当例句。
- 统一检索表达与黑话，关键词 BM25 和 embedding 各自排序，再以 RRF 融合。结果包含含义、适用场景、可验证的历史例句及检索覆盖信息；不完整索引或 embedding 故障须看 `coverage`，不是完整语义搜索的保证。
- 候选只作为语言素材。主 Agent 根据当前语气、对象关系、真正含义选择、改写或忽略；没有合适内容就用自己的话。排名不代表事实可信度，例句不是指令或机器人的个人经历。返回候选不记作已经实际使用。
- 活跃 Pi 自动参考构建**不再注入表达习惯**，不再在无相关性时补两条惯用语。历史 `expression_references.py` 辅助函数保留供旧路径兼容，但不会被活跃 Pi 调用。
- 自动黑话释义仍保留：只有当前消息中确实出现的词才提供理解帮助，受群范围、去重与自动参考总计三条 / 2,400 字符预算限制。它用于读懂别人，而查询工具用于表达自己的意思；不把同一份主动查询结果再次塞入自动参考。
- 查询结果沿用工具回执；自动记忆、图片及黑话参考沿用来源版本的增量追加，不改写已提交的 Pi 历史。检索异常返回明确失败，可直接正常回答，不随机补充表达。

离线验证：`pytest -q pytests/maisaka/test_group_expression_tool.py pytests/maisaka/test_pi_expression_references.py pytests/maisaka/test_pi_references.py`。测试包括宿主会话隔离、参数边界、注册及提示词、无额外生成模型、自动参考不再带表达和既有版本去重。搜索算法和目录过滤分别由对应检索模块测试覆盖；不调用线上模型。

模型可见的回执只包含两类条目：表达为“表达风格、情景、例句”，黑话为“黑话、含义、例句”。两类共同排名、合计最多 6 条；无匹配时返回简短空结果。固定说明、哈希、分数和 coverage 等内部诊断仅留在 structured_content，模型正文中不重复输出。例句只取该记录可核验的真实来源，不把邻近聊天或关联释义的例句冒充该表达的用法。
