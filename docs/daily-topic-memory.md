# 每群夜间最近话题（未部署，默认关闭）

这是可选的精简背景，不是新的 Planner，不要求主 Agent 顺着话题回复，也不替代实时原始消息、人物事实或现有压缩。辅助任务通过官方 Pi harness 的 `utils` 路由执行，无工具、无 QQ 发送权限；不增加 Python 模型客户端。不能保证消除遗忘、摘要错误或缓存失效。

## 一处启用

在实例 `config/bot_config.toml` 中设置以下自动生成的配置节（源码默认值在 `src/services/daily_topics/config.py`，配置版本 `8.15.66`）：

```toml
[daily_topics]
enabled = true
timezone = "Asia/Shanghai"
publish_hour = 3
publish_minute = 0
model_task = "utils"
max_topics_chars = 2400
max_batch_chars = 18000
max_batches_per_pass = 8
poll_seconds = 60
```

`model_task` 必须是现有 `model_config.toml` 的 `model_task_config` 名称；由 Pi 统一选择该任务的模型及限制，不引入第二套 key、模型或重试策略。全部设置由运行服务读取；改模型任务/长度预算用于下一次处理，已经开始的任务固定原分段大小以便重启续跑。已接受的分段不会因为换模型而重跑。字符预算不是 token 硬上限；Pi 的容量拒绝仍会让该段失败而保留进度。

默认北京时间 03:00 处理截至当天 00:00 之前的记录，边界为左闭右开自然日。03:00 前不会提前发布这一周期；停机后在恢复检查时补跑。可配置 IANA 时区和时刻；现有数据库的 naive 时间按应用原有**主机本地时间**解释，不擅自按 UTC 解释。跨 DST 的自然日可为 23/25 小时。

**初次启用**持久记录前一自然日 00:00 为采集起点，不自动花费模型预算回填整个历史数据库。该起点之后的已保存群消息会完整采集，之后重启、停机、乱序、晚到不按时间水位跳过。首次起点之前的历史不在覆盖声明内；仅存在于内存、尚未落库、已经删除的消息不能恢复。私聊不采集。禁用停止采集/发布/新注入，不删除已保存来源或已追加的主线程历史；重新启用沿原起点和游标恢复。

## 完整覆盖与失败语义

- 直接按 `mai_messages.id` keyset 扫描已保存群消息，不依赖 Luna 是否参与、主 Agent 最近 N 条或是否回复。包括已保存的用户和机器人发言；保存其真实 `session_id`、作者、平台消息 ID、源时间和完整可用文字。
- 图片/音频只使用已保存文字化描述或明确的无文本占位，不重新理解媒体、不声称看过原图。背景只来自消息证据；玩笑、猜测、转述和机器人说法不是已核实事实。
- 源镜像与导入游标一笔 SQLite 事务提交；游标锚点检查原始行指纹和最大 ID。数据库回滚、删除游标行或 ID 重用会明确失败，不能悄悄跳过；恢复备份时应将聊天库与 `data/daily_topics.sqlite3` 一起恢复并核对覆盖，不要直接清空游标。
- 每群每个到期周期冻结待处理源集合，按实际源时间和稳定序号排序。单条超长消息拆成带字符偏移的片段，所有片段进入辅助模型，不截掉尾部。每天量大时分段折叠旧板和新证据，每段保存中间板及进度。
- 一次调度超出段数预算仅返回 `incomplete`，下次检查继续；导入积压未追平时为 `importing`。没有任何半成品话题板可被主线程读到。后台模型失败、取消、JSON/schema/来源/长度校验失败不推进该段和覆盖水位；此前成功阶段保留。
- 并发工作者使用每群租约、续租与 revision 条件提交；过期工作者不能提交。完整板版本与整批源覆盖在同一事务发布。租约过期后可能重复计算一个未提交的无副作用模型段，不重复覆盖或发布。
- 每个发布周期最多成功处理一次。迟到消息或冻结后的新消息进入下一夜；若旧积压任务跨日完成，占用恢复当天的发布名额，剩余来源留到下一夜，**不会谎称已覆盖新一天**。job 中保留原 cutoff、源清单和发布日期，可核查未覆盖来源。
- “无变化”只确认覆盖，不产生新版本；整个完整话题板不变。清理所有话题必须明确返回 `[]`，发布 `cleared_no_active_topics` 新版本；空字符串/无效 JSON 是失败而不是清空。

## 引用与缓存

每轮主 Agent 仅检查当前不可变版，以 `daily_topics / 真实 session_id / version` 追加 reference。不是每轮替换 System；已有消息及旧引用逐字保留。新版本明确取代本群全部旧话题板，遗漏项不再活跃，空板撤销全部旧话题；事实发生日期不会被发布日期替换，晚到旧证据不得覆盖较新的更正。

Pi 已有的**当前可见引用**去重阻止同版重复追加；显式压缩移除该引用后，下轮可重新追加当前版本。检查发生在压缩维护之后。日话题不经过按当前词汇筛选的普通记忆相关性预算，避免只因这一轮不相关就漏掉清空/替代消息。常规白天输入仍照常进入原群的持久 Pi 线程；夜间辅助处理不锁主线程、不更换历史前缀。缓存是否命中仍由上游策略决定。

话题证据 ID 指向不可变源镜像，主 Agent 可用现有工具：

```text
read_thread_archive(event_ids=["daily-topic-source:message:123"], offset=0, limit=2800)
```

仅可读取自身真实群会话的已保存文字，返回采集时记录的消息 ID、实际时间和作者；出站消息的 ID 可能还是平台回执到达前的暂存 ID，后续正常回填不会使导入游标失效。稳定证据标识采用数据库源行 ID，而非可回填的消息 ID。按 `next_offset` 续读。不能把其他群的来源拿来作本群证据。摘要文本即使有来源也仍可能错误，所有引用都是不可信历史数据而非机器人指令。

## 运维与验证

日志显示 `complete / incomplete / importing / failed` 等状态，SQLite 的 `jobs`、`job_sources`、`sources.covered_day` 和 `versions` 可核对范围及待处理积压。若长期失败，应修复配置/模型容量/提示词或数据库恢复问题，不能靠跳过记录假装成功。源镜像和版本目前不自动删除，需纳入数据备份及磁盘容量管理。

纯离线回归：

```sh
uv run pytest -q pytests/services/test_daily_topics.py pytests/services/test_daily_topic_service.py
uv run pytest -q pytests/maisaka/test_pi_daily_topics.py
npm --prefix runtime/pi_agent test
```

三语提示词位于 `prompts/{zh-CN,en-US,ja-JP}/daily_topics.prompt`。不需要改主 Agent 人格、工具合同或旧压缩模板。上述测试使用离线模型回执，不涉及付费模型调用或真实 QQ 发送；生产启用后仍需观察实际摘要质量。
